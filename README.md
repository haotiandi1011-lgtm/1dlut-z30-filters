# 1dlut-z30-filters

> 把任意影调参考拟合成 256 点曲线，写进尼康 Z30 的自定义优化校准槽 C1–C9，写入前给出可量化的偏差报告。
> **不改固件、不刷机、不需要签名。**

**⚠️ 免责声明**：本项目通过逆向得到的私有协议与相机通信，属实验性工具。作者不对相机损坏、数据丢失、保修失效负责。
使用前请自行备份，并先在不重要的槽位试写。

---

## 这是什么

一个桌面工具 + 一个安卓写入端：

- **桌面端**：读风格参考（`.cube` / `.np3` / 单张照片 / 成对照片）→ 拟合成 256 点曲线 → 出偏差报告 → 通过 USB 写进机身
- **安卓端**：只做搬运——读配方包 `.z30` → 发 614 字节载荷 → 读回逐字节校验。不做拟合

Z30 机身自带 9 个自定义优化校准槽，官方只支持从存储卡导入，而且菜单里没有曲线编辑器。
本项目做的事就是：**把曲线直接写进这九个槽，一根 USB 线、几秒钟。**

## 它不是什么

- ❌ **不是固件修改**。不碰固件分区，不刷机，没有变砖风险
- ❌ **不是 3D LUT**。机身载荷里只有一条单通道曲线（512 字节 = 256 × u16），做不出分色相调整
- ❌ **不承诺 1:1 复刻任何滤镜**。统一口径是「近似 + 偏差报告」，数字说话

## 能力边界（真机验证过，别期待更多）

| 能做 | 不能做 |
|---|---|
| 任意 256 点影调曲线（抬黑、压高光、S 曲线、褪色、低反差、高光滚降） | 整体色偏（单曲线对三通道是同一映射） |
| 名称（≤19 字符 ASCII） | 分色相调整（HSL / Color Blender） |
| 锐化 / 清晰度 / 饱和度（参数区，真机验证） | 分离色调（阴影冷、高光暖） |
| 读写往返逐字节校验 | 去饱和 |

**为什么只能是 1D**：614 字节载荷里 `0x66` 起是 `512 B = 256 × u16`，单通道；三通道要 1536 B，3D 最小要 14.7 KB，物理上装不下。
完整的证据链（包括「为什么 NP3 拷卡这条路走不通」）见 [`设计决策-为什么是1D.md`](设计决策-为什么是1D.md) 和 [`负结果-NP3导入不带曲线.md`](负结果-NP3导入不带曲线.md)。

## 快速开始

### 桌面端（Windows）

1. 到 [Releases](../../releases) 下载打包好的 exe（免装 Python），或从源码运行：
   ```bash
   pip install -r requirements.txt
   python webui/server.py       # 自动打开浏览器
   ```
2. 用 [Zadig](https://zadig.akeo.ie/) 把相机的驱动换成 **WinUSB**（`Options → List All Devices → Nikon Z30 → WinUSB`）
3. 拖一个 `.cube` 进去 → 看偏差报告 → 选槽位 → 写入

> 换完 WinUSB 后 Windows 相册会认不出相机，要用相册时在设备管理器里「更新驱动程序 → 自动搜索」换回 MTP。

### 安卓端

到 [Releases](../../releases) 下载 APK，或看 `.github/workflows/android.yml` 的构建产物。

1. 电脑端导出 `.z30` 配方包，传到手机
2. 相机开机，用 C-to-C 数据线直连手机（需要手机支持 USB OTG）
3. 打开 App → 允许 USB 访问 → 导入 `.z30` → 选槽位（第一次建议 C9）→ 写入
4. App 会读回逐字节校验，显示「读回一致」才算成功

实测环境：iQOO Neo9 + 尼康 Z30，C 口直连，不需要 OTG 转接头。

## 安全模型

- 只写用户槽位 C1–C9，**不触碰固件分区**
- 写入前自动读回原槽位并备份（手机端存到应用私有目录，桌面端存到 `out/write/`）
- 写入后立即读回逐字节核对，不一致就报错，不做「自动补救」
- **`0x90CE`（删槽）是破坏性的，本项目不调用**。删除请用机身菜单
- 建议第一次写 C9

## 已知限制

- 只承诺 **Z30 固件 C 1.20**；其他版本的偏移需要重新定位
- **管线顺序是 LUT → 白平衡增益**（乘法）。同一份曲线在不同白平衡下效果不同，严肃复现请固定白平衡
- 有自定义曲线时，机身的**对比度 / 亮度参数被禁用**，写了也不生效，所以界面里没有这两项
- 名称字段只认 ASCII，中文会被替换成 `?`（机身限制）
- 36 字节的「仅参数」槽位（机身菜单手动创建）**没有曲线**；被 614 字节配方覆盖后无法原样恢复

## 关于预设名称

内置预设做过一次系统性改名。

早期版本里，部分预设名称与一些胶片 / 相机品牌的**注册商标偶然重合**。为避免任何混淆，全部预设名已改写为纯影调描述：

| 现在的中文名 | 机身上的 ASCII 名 |
|---|---|
| 胶片 03 · 淡彩 | `FL03-MUTE` |
| 电影 01 · 灰雾·压光 | `CN01-HAZE` |
| 黑白 01 · 提亮 | `BW01-LIFT` |

**所以：想按某个热门关键词（品牌名、型号名）搜索是搜不到的**——不是没有这类曲线，是名字已经统一换过了。
曲线、参数、排序都没有改动，说明里写的是这条曲线的实际影调特征（黑位、中灰、高光怎么走）。

## 踩过的坑（省你几个晚上）

1. **NP3 拷卡导入只带参数，不带曲线。** 三次不同构造方式的真机实验都「导入成功、画面正常」，但读回槽位只有 36 字节——曲线被固件丢弃了。详见 [`负结果-NP3导入不带曲线.md`](负结果-NP3导入不带曲线.md)
2. **`0x90CE` 删槽是破坏性的。** 不要把它当成「无害的前置清理」。上游项目就因此删掉过用户的预设
3. **Windows 上 pyusb 拿不到相机句柄。** MTP 模式下挂的是 WPD 驱动，必须换 WinUSB
4. **「导入成功」不等于「内容进去了」。** 判断曲线是否生效要读回、要台阶/直方图这类可量化特征，不能只看 UI 反馈
